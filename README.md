# YETRX

YETRX 基于 [mhtsec/ARTEX](https://github.com/mhtsec/ARTEX) 的 `a9d11cb` 原生源码维护，浏览器标题为 **YETRX-自主维护**，使用 Lucide 叶子图标。原项目说明保存在 [UPSTREAM_README.md](UPSTREAM_README.md)，许可证保留 AGPL-3.0；图标归属见 [web/THIRD_PARTY_NOTICES.md](web/THIRD_PARTY_NOTICES.md)。

## 原生 Agent 模式

Agent 是内置的一种普通对话模式，和其他模式共用 `ChatAgent`、模型配置、提示词管理和资源装配路径。没有内嵌 pi SDK、独立模型中继或 Node Agent 进程。

资源沿用上游管理方式：

| 资源 | 唯一管理位置 | 使用方式 |
| --- | --- | --- |
| 技能 | 全局 `skills/`（或配置的技能目录），系统 → 技能 | 全局启用；每轮读取当前文件 |
| 函数工具 | 原有数据库 `tools` 表，系统 → 工具 | 所有预设共享启用的实现、描述和参数默认值 |
| MCP | 原有 MCP 配置，系统 → MCP | 全局启用，保留技能按需解锁 |
| SDK 基础工具 | 上游 `DefaultTools()` | 所有原生模式共用固定工具集 |
| 模型与模式 | 系统 → LLM / Agent | 继续沿用模型绑定、会话选择、全局默认以及可编辑提示词 |

已启用资源对对话预设与探索角色共享，不再按模式绑定限制发现。旧绑定记录保留；全局禁用仍有效，编辑、禁用或删除在后续运行中生效。Skill 默认启用，页面可全局停用；需要任务、资产库或执行回调的操作只在真实上下文具备时装配。提示词预设继续引导任务分工，模型与预算设置保留。网络搜索使用系统全局开关，交互式 Shell 沿用既有独立开关。

首次将 Auto 原位改为 Agent 时保留 ID、对话、模型绑定和提示词历史，旧资源绑定引用一起迁移。已有 Agent 的自定义提示词、开关和绑定不会在重启时重置。Agent 的默认提示词只保留简洁工具说明，不复制个人身份提示或个人认证。

## 子任务与子代理：两套机制，分别管理

| 名称 | 定位与入口 | 标识与并发 |
| --- | --- | --- |
| **子任务（探索）** | 原版 Planner/Worker 探索机制。围绕探索目标持续规划，执行器领取探索意图、执行并写回探索记录；通过任务页面或 `spawn_task` 等探索入口使用 | 探索任务 `task_id`、执行事项 `intent_id`；每个探索任务默认 3 个 Worker 执行槽位，在「系统配置 → 子任务执行并发（探索）」调整 |
| **子代理（对话）** | `subagents` 按需启动独立会话，一次完成一件明确的求证、审查或小范围改写；报告实际操作、依据与结果，由主对话核验、决定是否采纳或合并 | `run_id` / `label`，用 `subagents_control` 管理；每个父对话独享 4 个并发名额，同一对话的多批运行共用；不同对话互不占用，与探索执行槽位独立 |

探索根任务仍称「探索任务」，内部领取的一条探索意图是一个子任务执行事项；Worker 是可复用的执行槽位，不是累计创建的任务数。两套机制均保留，接口、ID、历史、调度逻辑和资源绑定不因显示名称改变而迁移或重置。简短问答和一两步修改直接完成，不必派发子代理。

## 全局后台子代理

`subagents` 和 `subagents_control` 是原生全局函数工具，启用后由对话预设共享。每个子代理仍调用同一个 `ChatAgent`，从同一全局资源库读取配置；请求字段 `tasks` 表示本批次工作项，不是探索任务入口。

```json
{
  "tasks": [
    {"label":"inspect","task":"检查指定源码并给出证据。"},
    {"label":"review","task":"复核 inspect 的结论。","depends_on":["inspect"]}
  ]
}
```

独立任务并行，有依赖的任务按顺序执行；前置任务失败时后续任务标记 blocked。启动立即返回 `run_id`，完成后结果自动回到根对话；当前对话正在运行时，子代理执行记录和结果卡片统一排队：文字正在生成时不插入；当前这次模型响应结束的边界立即显示卡片，同一次对话里之后的模型请求在工具结果之后读取结果，不取消、不重跑正在执行的工具；若已在执行工具而没有流式文字，结果随到随显示并供下一次请求读取。最后一次响应之后没有后续请求时，沿用本轮结束后的自动跟进。无须轮询或再发一条消息。停止主聊天只中断当前回复；子代理继续执行并回传，未被模型读取的结果保留，在停止后自动跟进。使用 `subagents_control stop` 单独停止指定运行；删除会话会停止其子代理并清理回传队列。

控制动作：`list`、`status`、`read`、`stop`、`resume`、`message`。`read` 一次读取一个 label，最多末尾 8000 字符。默认每个父对话并发 4、每批最多 32 项；子代理硬性禁止调用 `subagents`、`subagents_control`、`spawn_task` 再次委派，追加工作交回主对话；探索内部 Planner → Worker 保持原有调度。状态保存在数据目录的 `workflows/`。

| 机制 | 当前行为 |
| --- | --- |
| 运行中指令 | `message` 向正在运行的任务排队，在下次模型调用前进入同一子会话；若先结束则丢弃，不打断正在执行的工具 |
| 恢复与编辑 | `resume` 可携带编辑后的 tasks；未变成功的一次性任务重排后仍复用，变更及其下游重跑，旧结果保留历史 |
| 检查点 | checkpoint 步骤持久化等待；通过匹配的 checkpoint_id/response 继续，支持 JSON null；服务重启不丢等待状态 |
| 命名会话 | thread 在一次运行内共享历史和固定 cwd；失败回合回滚，工作流恢复时重新执行 thread 回合 |
| 自动重试 | agent_retries 默认 0、最多额外 3 次；只重试可恢复错误，必须等旧执行器退出；每次使用新的一次性会话 |
| 额度恢复 | 提供商额度限制单独暂停，按 reset 提示和有上限的退避自动恢复，最多 5 次；手动 stop 取消定时器 |
| 源码目录 | 默认共享运行 cwd；显式 isolation:"worktree" 创建独立 Git 分支和源码树，默认保留，不自动合并，创建失败不降级 |

同次任务自动重试共享其工作树；恢复后重新执行的任务创建新工作树。`keep_worktree:false` 在执行器退出后删除该任务的工作树和分支。独立子会话不复制父完整历史。服务重启将仍运行的任务标为 interrupted，普通中断需手动恢复；resume 不恢复 Go 调用栈，也不保证工具副作用只执行一次。

五项机制参照当前 `zhyx111999/pi-workflows-lean` 源码，以原生 Go/ChatAgent 实现；模型仍继承父会话，并发数仍为 4，但按父对话分别计算，流程使用原生 DAG。详细契约和示例见 [workflow-authoring](skills/workflow-authoring/SKILL.md)，第三方许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

三个说明技能 `workflow-authoring`、`workflow-patterns`、`subagents-setup` 位于统一 `skills/` 中，已按原生工具重写。流程使用任务依赖，不执行旧 pi 的 JavaScript 工作流脚本。没有安装 Tavily。

## 探索长任务返回与复测

主对话调用 `spawn_task` 创建任务时，来源会话与任务在同一数据库事务中关联。主回复停止或网页关闭后探索继续；任务完成、失败、超时、删除或归档时，由后台收集器将状态送回来源会话，使用同一响应边界队列交给主模型读取实际证据。每个任务只记录首次交付；已交付后手动重开任务不会再次触发旧会话。删除来源会话会清掉关联，探索任务本身继续保留。

探索返回卡片幂等写入，未确认投递的记录会在服务启动后继续处理；模型执行与数据库确认之间发生进程崩溃时可能重新处理，不能据此假设外部工具副作用只发生一次。任务状态与漏洞是否修复是两件事，主对话需核对探索图、漏洞和执行记录。

结果有三个不同的状态：卡片已显示（任务链接记录 activity_id）、模型已读取（结果已交给当前模型对话）和已确认（本轮结束后写入 delivered_at）。复测只在结果被模型读取后才允许保存结论，仅显示卡片不算；中途读取的结果在读取它的那一轮结束时确认。

漏洞复测存在关联后台工作或尚未处理的返回结果时保持进行中。子代理仅返回证据，主对话处理完相关结果后才能保存唯一结论。默认复测提示词同步这一流程；升级仅替换精确匹配旧默认的正文，保留用户自定义提示词和版本历史。

## 会话流式显示

模型启用流式输出时，对话在生成过程中逐步显示文字；较大的片段会平滑展开，沿用原有气泡、Markdown、代码块和工具记录。已完成的历史直接完整显示，系统开启「减少动态效果」时直接显示收到的片段。

实时草稿通过已有认证体系下的 SSE 传到页面，完成后由原活动记录接替，每段回答仍只持久化一次。断线重连会补齐当前草稿和新记录；SSE 暂时不可用时保留原增量轮询作为补偿。用户向上阅读时保持滚动位置。模型设置为非流式时继续等待完整响应，不更改模型配置。

## 会话发文件

Agent 可调用全局 `send_file` 工具，将已生成的文件直接发到当前聊天。消息中显示文件名、大小和下载按钮；下载沿用现有登录认证。可在工具页面管理全局启用状态。

```json
{"path":"reports/result.pdf","name":"分析报告.pdf","caption":"报告已完成，可在这里下载。"}
```

相对路径按当前会话工作目录解析，也可发送绝对路径。支持普通文件，默认单个最多 128 MiB；可在「系统配置 → Agent 文件发送」中按 MiB 调整，0 表示不限制大小。保存后对下一次发送生效，无需重启；目录先打包。服务端保存独立副本，源文件修改或工作树删除不会改变已发附件；删除会话会清理该会话的附件。子代理将产物路径交给主代理，由主代理审查后发送。

## 执行进程与资源限制

主聊天、对话子代理、Planner、Worker、MainAgent 和第 0 轮目标拆解的 Norma 会话循环默认运行在受监督子进程。SDK 文件/Bash、交互式 Shell 和自定义 command/script/http 在执行进程运行；MCP 的连接、发现与调用使用独立受限 helper。网站保留模型路由、限速、计量、审批、数据库及协调。

Linux 需要 cgroup v2 与 systemd `Delegate=yes`，服务使用 `KillMode=control-group`。启动先准备限制并验证子进程握手，无法实施限制时明确失败。Windows 使用嵌套 Job Object；其他平台目前需显式设置 `ARTEX_EXECUTION_ENABLED=false` 使用原生进程内路径。关闭开关不会删除用户数据或配置。

可选 MCP 的配置、连接或工具目录错误沿用原有容错：记录错误，继续装配其他已启用资源。进程启动、硬限额、容量、IPC 和清理错误会阻止本次执行，绝不转到未隔离路径。

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `ARTEX_EXECUTION_ENABLED` | `true` | 启用进程隔离 |
| `ARTEX_EXECUTION_MAX_SESSIONS` | `8` | 同时运行的 Agent 会话上限 |
| `ARTEX_EXECUTION_MEMORY_MIB` / `ARTEX_EXECUTION_CPUS` / `ARTEX_EXECUTION_PROCESSES` | `512` / `1` / `128` | 每个 Agent 及其后代的硬限制 |
| `ARTEX_RESOURCE_MAX_WORKERS` | `16` | MCP 与管理页测试 helper 总数 |
| `ARTEX_RESOURCE_MEMORY_MIB` / `ARTEX_RESOURCE_CPUS` / `ARTEX_RESOURCE_PROCESSES` | `384` / `1` / `128` | 每个 helper 及其后代的硬限制 |
| `ARTEX_EXECUTION_TOTAL_MEMORY_MIB` / `ARTEX_EXECUTION_TOTAL_CPUS` / `ARTEX_EXECUTION_TOTAL_PROCESSES` | `3072` / `4` / `1024` | 所有 Agent/helper 的聚合硬限制，网站进程不计入 |

CPU 值以逻辑核心为单位，Linux 的进程数同时计算线程。容量满时明确返回忙碌；同一 transcript 不允许并发写入，真实进程树退出后才释放容量。主停止仍只取消当前会话，后台任务由各自取消入口控制。共享目录组织文件；此功能不增加文件系统或网络权限沙箱。

## 历史聊天查阅

Agent 可用三个只读工具查阅历史会话，数据来自数据库中的会话活动账本，不读取模型密钥等配置表：

| 工具 | 用途 |
|---|---|
| `list_chat_sessions` | 按最近更新时间从新到旧列出会话（稳定排序、游标分页，每页最多 50 个），返回 id、标题、时间、条数和 `/chat?c=<id>` |
| `search_chat_sessions` | 按字面量搜索标题和正文（大小写不敏感，支持中文，`%`、`_`、`\` 不是通配符），每个会话返回最近一处命中的片段和可直接传给读取工具的 `read_cursor` |
| `read_chat_session` | 按发生顺序分页读取一个会话：每页最多 50 条、正文默认 6000（最多 12000）字符；超长单条会切成带 `truncated` 标记的片段，用 `next_cursor` 逐段续读 |

默认只搜索、读取用户消息和助手回答（包括最终回答），`include_tools=true` 才包含工具调用与输出，推理过程从不对外。每个结果以「以下是历史聊天记录数据」声明开头，历史里的指令只作为数据呈现，不当作新指令。工具由所有预设共享，可在工具页面统一启用或停用。

## 构建与运行

需要 Go 1.26 和用于前端构建的 Node.js；服务端运行不需要 pi 或 Node Agent 运行时。保留 `artex` 二进制名和 `ARTEX_*` 环境变量，以兼容已有部署。

```bash
./build.sh --target linux/amd64
# 部署生成的 artex、skills/ 以及现有配置和数据。
./artex -addr :18787
```

数据库、模型密钥、JWT 签名密钥、历史和用户编辑的技能属于现有实例，应保留，不能用源码包中的默认文件覆盖。工具以服务用户身份运行；对话与子代理工作目录用于组织文件，执行资源由上述独立进程及 OS 硬限制管理。

旧内嵌版本的源码保存在 `archive/pi-integration` 分支。使用过旧运行时的对话，在首次原生运行前从活动记录重建上下文，旧工具调用作为历史文字保留，避免重放。原始文件和旧原生 transcript 副本保留供回溯；网页记录不删除。

版本检查指向 `zhyx111999/YETRX`。原生二进制更新路径保留；全局技能仍由技能管理维护。Docker 发布只有显式配置本仓库的 `PUBLISH_DOCKER` 与 `DOCKERHUB_IMAGE` 时启用，默认使用原生部署。

验证范围及已知上游限制见 [VALIDATION.md](VALIDATION.md)。
