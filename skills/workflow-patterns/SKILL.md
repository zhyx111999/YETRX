# 子代理分工范式

先判断是否值得拆分。简短问答、一次读取或单点改动由当前模式直接完成。有明确范围、值得独立求证或可并行的小事才交给 `subagents` 子代理；每个子代理只负责一件事，有先后关系时用 `depends_on` 连接。子代理报告实际操作、依据和结果，由主对话核验并决定是否采纳或合并。

需要围绕一个探索目标持续规划、领取探索意图并执行时，用 `spawn_task` 等探索子任务入口，不用子代理代替整套持续探索流程。探索子任务使用 task_id/intent_id；子代理使用 run_id/label，状态和并发独立。

## 并行核查

给不同任务分配不同范围，例如接口、数据迁移、前端展示；说明各自只负责一个范围。源码修改在运行 cwd 指定项目，给任务设置 `isolation:"worktree"`；默认保留独立分支/工作树，由主对话对照报告检查差异再集成。

## 研究与汇总

```json
{
  "tasks": [
    {"label": "sources", "task": "查找本次问题的原始资料，给出日期、出处和证据；标明无法核实的部分。"},
    {"label": "constraints", "task": "独立核对当前项目的约束和已有实现，列出具体文件和依据。"},
    {"label": "synthesis", "task": "结合两项结果回答问题；核查冲突证据并明确不确定性。", "depends_on": ["sources", "constraints"]}
  ]
}
```

先在 task 中补齐实际问题和输入位置，再调用工具。联网能力取决于该模式已开放的全局工具和 MCP；此技能不会安装搜索服务或读取额外密钥。

## 实施后复核

实施任务输出改动副本的位置、差异和实际验证结果。审查任务通过 `depends_on` 等待实施完成，再读取该副本并独立核查。主对话最终决定是否集成，不能把子代理自报的“通过”直接当成整个项目通过。

需要中途修订要求时用 `subagents_control message`。需要编辑后续跑时用 `resume` 的 tasks，未变成功步骤可以复用，变更项及其下游会重跑。审查需等待明确响应时，可在步骤间加入持久化 checkpoint。

后台完成会自动回传；主聊天停止仅中断当前回复，不取消后台执行和结果回传。指定子代理运行用 subagents_control stop 单独停止。主对话正在输出时先排队，在本轮输出及工具执行结束后立即依序送入，不打断本轮。同一父对话的多批子代理运行共用该对话的并发名额，不同父对话各自独立。用户要求查看时，用 `subagents_control read` 明确提供 run_id 和 label，一次读取一个子代理，最多末尾 8000 字符。需要更多上下文时读取子代理保存的文件。
